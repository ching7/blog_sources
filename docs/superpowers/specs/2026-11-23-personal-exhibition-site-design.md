# 个人展厅站点 · 设计文档

日期：2026-11-23　仓库：`blog_sources`（推翻现有 Hugo + PaperMod 博客，原地重建）

## 1. 意图

作者（AI 应用架构师，GitHub `ching7`）的个人网站。定位是**「一个人的展厅」**，不是简历网页版：来访者先感受到"这个人有趣、有审美、有自己的思考"，再看技术细节。用途是后续求职和个人展示。

用户原话里的三个关键词：**有趣、风格统一、有个性**。

## 2. 目标 / 非目标 / 反目标

**目标**
- 首页是一张"手绘工作台"，桌上摆四件物件，对应四个展区：仓库、审美、探索、笔记；另有一件「打卡本」展示活跃度（见 §5）。
- **个人经历不做重点展示**（用户决定）：网站的任务是让人对这个人产生兴趣；想了解履历的人会自己去找。因此经历不上桌面，并入安静的 About 页。
- 每个展区有一个固定的日本传统色作"身份色"；全站藏几件可以上手玩的小物件（动态猫、笔筒换色等）。
- 求职用的硬信息（经历、联系方式、技术栈、代表项目）收在一个安静的「About」页：从导航或页脚能找到，但不抢主调。
- 迁入现有 25 篇 Java 笔记（原型里写的 30 篇有误，以实际为准），作为站内「笔记」角落。
- 沿用 GitHub Actions → Cloudflare Pages 的部署方式，绑定用户的 ipv64 域名。

**非目标（v1 不做）**
- 多语言（只做中文）、评论、**站内搜索**（*我的判断*：25 篇规模用不上，省掉 Pagefind 之类的依赖；旧 `/search/` 重定向到 `/notes`）、标签云（RSS 可保留但不设计）、CMS 后台、暗色模式。
- 自有服务器部署（华为云 / AMS 都不用；AMS nginx 仅作为日后大陆访问慢时的兜底，不在本次范围）。

**反目标（做到了也算失败）**
- 看起来像套了模板的作品集 / 博客。
- 炫技过度：满屏动画、加载慢、互动喧宾夺主，让人找不到内容。
- 风格割裂：各展区像不同的人做的。笔记页尤其不能退化成另一套"普通博客"外观。

## 3. 视觉方向（已定）

用户在三个可交互原型中选定 **C「手绘工作台」为主，按需加入 A「传统色」**。

**首页两种模式（2026-11-24 用户追加）**：用户觉得 v3 偏花哨，要一个简约版。
- **简约（默认）**：确认稿 `minimal-v2.html`。单栏最宽 760px；欢迎语 + 小号动态表情 + 右侧小猫（「戳我」）；四件物件是一份竖排清单（身份色圆点 + 比喻标题 + 灰色说明 + 右侧展区名），悬停时右移、标题出现身份色荧光笔、右侧浮出动态表情；打卡本缩成一条细热力图 + 一行数字；页脚「关于我」+ 8 个色点换强调色 +「弄乱桌面」。
- **热闹**：确认稿 `c-v4.html`（即 v3 压进首屏：猫挪到欢迎语右侧，笔筒和「整理桌面」在左下）。
- 两者互相切换，**不记住访客选择**：每次进站都是简约。
- **统一操作位（用户要求）**：两种首页的可操作元素位置和交互方式一致——**右上**＝猫（气泡文案相同「戳我，或者敲敲键盘」，点按或敲键盘触发）；**左下**＝「关于我 →」文字链接；**右下**＝换色控件（简约版为色点、热闹版为笔筒，都是单击换色）紧挨着最右下角的模式切换按钮（简约版「弄乱桌面 🙃」/ 热闹版「整理桌面 🧹」）。切换按钮两版同一样式：高 30px 胶囊、1.5px 墨色虚线边、纸白底，悬停/键盘聚焦变实线墨底白字。所有可操作元素都用 `<a>`/`<button>`，可键盘聚焦，不做只靠悬停才能触发的功能。
- **首屏原则**：两种首页在 1280×720 及以上视口里所有内容一屏可见、不滚动（两份确认稿已用浏览器在 1280×720 实测不溢出）。窄屏手机（宽 < 720px）允许纵向滚动（*我的判断*：手机上塞进一屏会小到不可读）。
确认稿：`.superpowers/brainstorm/*/content/c-v3.html`（最终，2026-11-24 用户确认「非常好」）；色彩机制见同目录 `c-with-a-v2.html`。均已 gitignore，本地可直接打开。

**隐私（2026-11-24 用户追加）**：全站（含 About 与旧笔记）不显示名字、公司等个人信息。About 标题用「关于我」，工作经历表去掉「组织」列；旧笔记里的用户名、示例域名、前东家包名等替换为中性占位。

**v3 定下的规则（用户要求）**
- **首页不出现名字**。欢迎语从一组有个性的句子里随机取一句，点击换一句，配一个动态表情（例：「嗯？你也走到这儿来了。」「这里没有简历，只有一张乱桌子。」「今天也没有 OOM，真好。」）。
- **物件不直白**：每件用比喻命名并配一句俏皮说明，展区正式名缩成角落带身份色的小签。仓库=🎁「拆盲盒」、审美=🌈「偷来的颜色」、探索=🚀「可能会炸」、笔记=🦕「考古现场」、打卡本=🔥「最近有没有偷懒」。文案措辞可由 builder 打磨，但不得编造事实（如 38 个收藏、25 篇、2020 年须与实际一致）。
- **大号动态高清 emoji**：用 Google Noto Animated Emoji（CC BY 4.0，需在站内署名），512px webp **下载自托管**，不从 `fonts.gstatic.com` 实时加载。并非每个 emoji 都有动态版，选用前要确认存在。适度使用：每件物件一个、欢迎语一个、少量交互反馈（如抽笔时冒 ✨）。
- **打卡本热力图照实展示**（*我的判断*，用户未表态）：近一年公开提交稀疏，标题「最近有没有偷懒」本身把稀疏变成自嘲。
- **猫用动态表情猫，不固定在右下角**（用户选定）：放在桌面上显眼、一看就能玩的位置（例如蹲在物件之间或欢迎语旁），带明确的可交互提示（如「戳我 / 敲键盘」），悬停有反馈。键盘输入或点按都会让它动起来，攒够次数冒一句话。

- **底**：米色纸面 `#f3ecdf` + 浅点阵网格；墨色 `#2b2b2b` 粗描边，略不规则圆角；卡片轻微随机旋转，悬停摆正上浮；实心偏移投影。
- **手写感字体**：楷体气质。系统楷体不是每台设备都有 → 自托管开源字体「霞鹜文楷」并按实际用字做子集（builder 的取舍，见 §7）。正文长文（笔记）可用更易读的字体，但描边、色彩、版式语言保持一致。
- **身份色（固定）**：About 藍 `#0D5661`（只用在 About 页本身）、仓库 瑠璃 `#005CAF`、审美 鴇 `#EEA9A9`、探索 若竹 `#5DAC81`、笔记 白鼠 `#BDC0BA`。体现在胶带、投影、色名小签；进入该展区后作为该区主色。
- **全站强调色（可变）**：默认 山吹 `#FFB11B`，用于荧光笔划线、高亮。笔筒（热闹版）/ 色点（简约版）可换成其它传统色；与模式一致，**不持久化**，刷新回到山吹。
- **手绘元素**：用 Rough.js / RoughNotation 画手绘边框、下划线、高亮。
- 视觉细化：用户会在本地 Open Design 里基于确认稿细化。实现以确认稿 + 本节 token 为准先搭起来，Open Design 定稿后再对齐细节。

## 4. 站点结构

| 路径 | 内容 | 说明 |
|---|---|---|
| `/` | 首页 · 简约（默认） | 随机欢迎语（不出现名字）+ 四件比喻物件清单 + 细打卡本 + 小猫 + 色点；页脚链到 About 与「弄乱桌面」 |
| `/desk/` | 首页 · 热闹 | 工作台版：四件卡片物件 + 打卡本卡片 + 大猫 + 笔筒；左下「整理桌面」回 `/` |
| `/repos` | 仓库 | 精选展品，每件配一句点评（ppt2video、ai-roundtable、prompt-me 等，取自 GitHub 首页表格）；数据放本地数据文件，不在构建时调 GitHub API |
| `/aesthetics` | 审美 | 收藏的颜色、画、插画、喜欢的站点，以及本站自身的设计说明 |
| `/explore` | 探索 | 小玩具、实验、半成品 |
| `/notes` | 笔记索引 | 25 篇按原分类列出 |
| `/posts/...` | 笔记正文 | **保持现有 Hugo 实际生成的 URL 不变**（小写路径，如 `/posts/05.opensource/12.ppttovideo/ppttovideo/`），避免已有外链失效 |
| `/about` | About | 叙事体自述（延续 GitHub 首页口吻："OOM 没躲过去，只是变成了显存版"）+ 代表项目（金融行业智能体平台、AI 训推一体平台）+ 技术栈 + 带团队经历 + 联系方式；排版克制，像桌角的一张名片 |

所有内容页共用同一套纸面、描边、色彩语言；每页可在显眼处保留猫或其它小物件作为一致的"签名"。

## 5. 互动物件（v1）

- **猫**：动态表情猫，位置与交互见 §3「v3 定下的规则」；移动端只靠点按。
- **笔筒**：抽一支笔切换全站强调色。
- 其它展区各自的小玩具由 builder 视内容提议，每区最多一个，遵守反目标。
- 所有动效尊重 `prefers-reduced-motion`；不依赖互动也能读完全部内容。

- **打卡本（首页，用户追加）**：上半页是 GitHub 提交热力图（近一年，手绘风格，格子用当前强调色、随笔筒换色）；下半页像计步器列出 linux.do 的累计数字（访问天数、阅读时长、已读帖子等，具体字段以用户公开资料页实际可见为准）。数据在构建时读本地数据文件，页面不在浏览器里实时请求。

### 活跃度数据的获取

- **GitHub**：抓 `https://github.com/users/ching7/contributions`（公开 HTML，无需 token，2026-11-23 实测可用），解析每天的 `data-date` / `data-level`。GitHub Actions 加每天一次的定时触发，抓取后重新构建部署。抓取失败时沿用上次提交进仓库的数据，不让构建失败。
- **linux.do**：脚本请求会被 Cloudflare 人机验证拦截（2026-11-23 实测 403 "Just a moment..."），Actions 上同样不可行；Discourse 公开数据只有累计数字，没有逐日访问记录，因此不做热力图。采用**半自动**（用户选定）：本机一条命令用真实浏览器（Playwright）打开 linux.do 过验证，取 `/u/ching7/summary.json` 与 `/u/ching7.json`，写入数据文件并提交推送。2026-11-24 已用 Playwright 浏览器实测通过验证、两个接口均返回 200，`can_see_summary_stats: true`。
- linux.do 展示字段（我的提议）：`days_visited`（泡了 N 天）、`time_read` 秒数换算为小时（读了 N 小时）、`posts_read_count`（刷过 N 帖，过万写「2.4 万」）、`trust_level`（信任等级）、`created_at`（加入于 YYYY-MM）。实测值供参考：102 天 / 141560 秒≈39 小时 / 24013 帖 / 等级 2 / 2026-06-10 加入。可选一个每日跑的 nohup 守护循环；**不用 launchd**（launchd 进程无权访问 `~/Downloads`，会以 78 退出）。
- 数据文件提交进仓库，页面上标注「更新于 YYYY-MM-DD」。

## 6. 技术方案

**考虑过的三种做法**

| 方案 | 取舍 | 结论 |
|---|---|---|
| A. Astro + 手写 CSS + 原生 JS | 每件物件是一个组件，样式脚本同文件；默认零 JS、按需加载（孤岛）；笔记用内容集合。代价：引入 Node 依赖，笔记 frontmatter 小幅迁移 | **选定** |
| B. Hugo + 自写主题 | 零新增依赖、构建快；但 Go 模板写组件别扭，物件一多脚本散落。Hugo 的大站构建优势在 30 篇规模用不上 | 放弃 |
| C. 纯手写 HTML | 最自由；但笔记要渲染 Markdown，终究要自造构建脚本 | 放弃 |

用户选 A，理由：站点核心是"一件件可玩的物件"且会持续增加，与 Astro 孤岛模型吻合。

**已定**
- Astro（当前稳定版），**不引入 React/Vue 等 UI 框架、不用 CSS 框架/组件库**；互动用原生 JS。
- 手绘：Rough.js、RoughNotation；本机抓取脚本用 Playwright（只用于 linux.do 更新脚本，不进站点产物）。除此之外新增依赖需说明理由。
- 包管理与构建用 arm64 node（`/opt/homebrew/bin/node`），本机无 bun。
- 部署：改 `.github/workflows/deploy.yml`，用 Node 构建 `astro build`，wrangler 部署 `dist/` 到现有 Pages 项目 `cyn-blog`（secrets 已配置）。
- 删除：PaperMod 子模块、`hugo.toml`、Hugo archetypes、Hugo 专用页面；`scripts/migrate.py` 是一次性脚本，可一并删除。
- 字体、图片全部自托管，不引外部 CDN（大陆访问考虑）。

## 7. 留给 builder 的决定

- 目录结构、组件拆分、CSS 组织方式（推荐 CSS 自定义属性承载色彩 token）。
- 霞鹜文楷子集化的具体工具与流程；正文字体选择。
- 笔记迁移：frontmatter 映射、`/images/...` 图片路径、代码高亮方案，只要 URL 与图片可用。
- 笔记里外链图片（*我的判断*）：24 张托管在 gitee.com 的下载进站内自托管；4 张指向 `192.168.x.x` 内网地址的已无法获取，标注为失效图片。
- 各展区小玩具的具体创意（每区 ≤1）。
- 移动端布局（桌面网格折成单列即可，物件旋转保留）。

## 8. 文案来源

- 自述、两个代表项目、仓库点评：**原文照搬** GitHub 个人主页 README（`github.com/ching7/ching7` 的 README.md），不改写事实。
- 原文缺的部分（技术栈汇总、带团队经历等）：builder 起草并标注「待确认」，用户改定后再上线。实现计划里要有单独的文案确认步骤。
- 首页物件：v1 用卡片 + 动态 emoji（v3 定稿，取代之前的「手绘线稿图标」方案）；Open Design 画好真正的物件插画后可再替换。

## 9. 依赖用户的事项

- **自定义域名**：用户已申请 `xxx.ipv64.net` / `xxx.ipv64.de` / `xxx.home64.de`，均可由 Cloudflare 托管；主域名待用户指定，其余可 301 到主域名。在此之前站点先跑在 `cyn-blog.pages.dev`。
- **内容素材**：审美、探索两区的具体条目，About 页的联系方式（邮箱 / 微信等公开到什么程度）由用户提供；先用 GitHub 首页已有内容和占位填充。
- 视觉细化在 Open Design 完成后回灌。
- 功能与观感验收由用户在浏览器里手动进行。
